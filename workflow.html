Distance and clustering workflow

  1. Place waveform CSV files in input_files/; retained selected-channel rows are trimmed to a shared length automatically.

  2. Select one or more numeric sensor columns.

  3. Select one of the five alignment methods.

  4. Compute all unordered waveform pairs, optionally across multiple GPUs.

  5. Save the symmetric all-channel and per-channel distance matrices.

  6. Apply hierarchical clustering to the combined matrix and separately to each channel-specific matrix.

  7. Save assignments, silhouette diagnostics, and manuscript-style figures.

GPU parallelization

The parent process converts the selected CSV columns to a shared read-only memory map. One worker process is launched for each selected GPU. Worker r processes the outer-loop indices satisfying i mod number_of_workers = r, so workers never write the same pair. Each worker stores one partial NPZ file and a progress log. The parent merges these files after all workers finish.

Parallelization changes neither candidate offsets nor distances. It only distributes independent waveform pairs.

Default clustering

Average-linkage agglomerative clustering operates directly on the precomputed distance matrix. A fixed cluster count can be supplied; otherwise the package selects the candidate with the largest silhouette score. Single and complete linkage are also available. Recursive within-cluster subclustering is enabled by default at depth one. Set --subcluster-depth N to choose the number of nested levels, or use --subcluster-depth 0/--no-recursive to disable it.

Optional MDS/Ward clustering

--clustering mds_ward embeds the distance matrix with metric multidimensional scaling and applies Ward clustering in the Euclidean embedding. This is retained for comparison but is not the default.
